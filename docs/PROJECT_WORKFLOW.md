# 小作文观察工作流

本文件描述截至 2026-10-13 已实现的业务规则和运行边界，供维护和审阅；不包含私有内容、实测原文或本机目录。

## 流程

人工触发 → 固定时间窗口与预算 → 分页保存全部原文 → 选择未处理的纯文字 → 小批次内完成分类抽取、证券匹配、独立复核、观点入库 → 按配置自动发布高置信且通过门禁的观点 → 保存检查点后自动处理下一小批 → 人工处理疑点 → 看板读取已发布观点。

默认回看最近 7 天。原文按 topic_id 去重，正文变化保存旧版本；处理状态还关联内容哈希及模型、规则、主表版本。相同配置下已经处理的接受、排除和存疑主题不重复调用；存疑进入人工队列。程序中断可续跑，成功阶段不重复付费。

抓取的临时连接故障在同一游标最多尝试3次，认证或权限异常不自动重试；每页原文提交后再推进游标，防止跳页和重复计数。

图片、文件及空正文主题保存接口原文和排除原因，不下载附件或做 OCR。只有具备卖方分析风格的具体 A/H 公司与明确方向才结构化。宏观、行业、纯新闻以及美股内容可留原文，不强行生成个股观点。

## 结构化与审核

- 每篇同公司只保存一条综合观点。保留方向、目标价、币种、来源、证据与审批轨迹。
- 市场使用 SH/SZ/BJ/HK；没有 H 标记时优先唯一 A 股，AH 必须证明同公司的两个上市主体。
- 标的由 Tushare 主表与本地别名确认；有歧义或未匹配的名称留待解析，尚未自动联网补码。
- 推荐关注、高弹性、受益等结合上下文判断看多，否定词、风险及最终结论不能忽略。
- 券商只取明确署名；无署名保持 NULL，未注明研究组记“其他”。不能依据文风猜券商。
- 目标价仅为每股价格；市值、估值倍数、增长率不当作股价。所有证据必须能精确回到原文。
- 二审逐条给出接受、修正、排除或存疑，可补齐漏项；当前使用两次模型调用，并非盲测评估。

明确接受还须通过本地证据、唯一匹配、方向、来源及价格门禁。当前置信度门槛不等于已验证准确率。已有人工决定和已发布结果受到保护。编辑会使旧审批失效，必须重新审核。

## 状态与发布

原文保存、候选存疑、已接受及已发布是不同状态。`automation.auto_publish=true` 时启用独立二审后的自动发布；公开配置模板默认关闭，实际运行以本机配置及冻结批次设置为准。识别与独立审核各调用一次，不为发布再增加第三轮模型调用；模型置信度不是经评测得到的真实准确率。本次冻结批次剩余队列已显式切换为 gpt-6-luna、低推理强度，不代表公开模板或其他批次同步切换。

自动发布只选择指定工作流批次内、原文抓取及选题已经结束、单篇识别与复核已闭环的观点。要求本批审核模型的有效 AI 接受记录、明确卖方分类、观点和审核置信度均不低于0.95、无主题级未解决疑点，再通过全部现有证据、证券、来源、价格及去重门禁。新增审核条件未通过的 AI 观点转入人工候选，不能覆盖已有人工决定；不扫描发布旧库全部已接受记录。

发布前备份数据库，在事务内重新核验审批指纹、证券、证据、疑点与自动发布资格；发布状态、发布批次与自动发布审计同一事务提交，失败回滚。已发布观点不重复发布，也不覆盖人工决定。自动发布的处理单位改为**已闭环的小批/单篇观点**：整个7天队列可以尚未完成，但未识别、未复核或失败文章绝不发布。原管理页“手动发布整个批次”仍要求批次全部完成，两个入口的范围不同。本地热度和历史搜索只读取已发布观点。

`npm run workflow:validate-batch -- --batch=编号` 只读检查批次、原文版本、证券关系、有效审批、调用账本、外键及数据库完整性，不能代替语义抽查。

## 成本及当前缺口

`workflow:recent` 是推荐的最近7天入口：最多选择 5,000 篇，每组最多10篇且受输入字符上限约束。每次触发默认最多新增20次 CLI 调用、300,000 输入字符、60分钟；上海自然日所有批次合计最多40次调用及600,000输入字符。失败和中断的预留调用也计入预算，跨批次不会清零；调用前在数据库写事务中核验每日及批次预算。原文抓取不消耗模型调用预算，仍受时间和页数上限保护。

经用户明确授权，可对指定冻结批次使用 `--unlimited-calls`：该批次不再受批次或每日调用次数上限约束，全部调用仍逐次记账；其他批次的默认上限不被关闭。字符和时长预算仍独立生效，可显式提高到足够完成这轮有限队列的数值。不意味着无限网络重试、不静默切换模型，也不扩大原文范围。

快速处理可用 `--concurrency=4`，最多四路独立小批并行，每路仍完成识别和独立复核；已有首轮结果的复核也可并行，复核仅处理自己小批，发布串行排队。任何一路遇到需整批暂停的错误，不再分配新小批，并等待在途付费调用结算和保存后才释放运行租约。采用低推理强度，不启用额外加价的服务等级。

每个小批完成首轮后立即复核入库，续跑优先复核已付费识别结果。启动新付费识别前至少保留两次调用空间，避免用最后一次额度只识别不复核；重试、二审拆组或输出变长仍可能耗尽预算，此时保留已识别结果，下次优先复核。输入字符在实际调用前严格检查，不承诺用预算估算代替真实计量。

复核输入完整保留原文和首轮观点，候选列表不再重复复制整条观点；紧凑输入格式单独记录版本，缓存键包含实际输入。CLI 内部网络请求及账号美元费用不完全可见，调用次数和字符数不是精确费用。

首轮合批按12,000字符分组；复核包含首轮结果，单独按40,000字符分组，而不是继续沿用首轮的小上限造成大量零散调用。两轮均最多10篇，实际完整提示词仍受安全上限与每日字符预算约束。调整分组不截断原文，也不降低证据门禁。

结构错误或文章编号不对齐时暂停，不按相似度猜编号、不自动拆成大量单篇重试。`--keyed-output` 使用每篇文章编号作为必填对象键，通过严格 Schema 校验，避免数组中的重复编号造成漏项；旧数组格式仍兼容。

模型不静默切换。显式续跑可指定 `--model=模型ID`，必要时指定 `--codex-cli=新版CLI绝对路径`，两轮使用同一指定配置。模型或客户端变更写入 `workflow_model_transitions`，列明变更前后配置及沿用的已完成主题；已完成主题不重复推理，既有发布记录不改写，已保存的首轮结果可直接续接复核。沿用不代表旧记录由新模型重新识别。预检检查登录与客户端；缓存模型目录可能滞后，显式指定客户端时允许带可用性未确认提示进入真实调用，真实调用失败仍暂停，不静默降级。

原文证据不匹配、单篇候选未全部裁决或修正缺少完整观点时，不自动接受、不写入可发布观点、不自动重付费，保留审计后转入人工存疑队列，其余文章继续。整批 JSON 结构错误、文章编号错配、账号异常及原文版本变化仍会暂停整批，防止错误扩散。

`workflow:recent` 再次触发会接续最近7天内未完成的准备/预算暂停批次；累计调用和输入量不重置，只按本次允许新增预算和每日剩余额度设置累计上限。非预算异常或人工停止不得静默重试，检查后须显式续跑。冻结窗口完成后，下次触发才开启新的最近7天窗口；不会在同一次触发内无限建立新批次。

目前实现了触发后的自动小批闭环、可配置自动发布、跨批次每日预算和再次触发时的断点接续；**尚未启用每天定时触发、系统重启自启动及自动主表刷新**。电脑睡眠、退出或预算耗尽后不能承诺自行唤醒运行，不应称为成熟无人值守系统。

兼容入口 `workflow:run` 仍按本机配置的原批次预算运行，显式 `--resume=编号` 不自动提高累计上限。管理页原“继续批次”也保持这一含义。

## 日常操作

```powershell
npm run workflow:recent
npm run workflow:automation-status
# 仅抓取最近7天原文、准备去重队列，不调用模型
npm run workflow:run -- --hours=168 --limit=5000 --prepare-only
# 显式续跑指定批次；只有必要且获授权时才调整累计预算
npm run workflow:run -- --resume=编号
# 为指定批次显式开启自动发布并续跑
npm run workflow:run -- --resume=编号 --auto-publish
# 明确授权后快速处理这个冻结批次，不再限制调用次数
npm run workflow:run -- --resume=编号 --unlimited-calls --concurrency=2 --batch-size=10 --max-chars=10000000 --max-daily-chars=10000000 --max-minutes=720 --auto-publish
# 仅发布指定批次已符合自动门槛的观点，不发起新模型调用
node scripts/automated_workflow.mjs publish-ready --batch=编号
```

后台启动需隐藏窗口并将日志留在本机。每日预算以模型调用账本的上海日期计算，`status` 及 `/api/automation/status` 返回 `daily_budget`。模型处理涉及私有正文传输，必须在获授权的数据范围内执行；代码入口不替代内容授权。

## 维护入口

| 文件 | 作用 |
| --- | --- |
| config/workflow.example.json | 可公开配置模板；实际运行读取本机 workflow.json |
| scripts/automated_workflow.mjs | recent / run / status / stop 入口 |
| scripts/lib/recent_pipeline.mjs | 最近7天队列选择、预算暂停接续及异常保护 |
| scripts/lib/automated_pipeline.mjs | 抓取、选题、首轮、二审及持久化 |
| scripts/lib/note_normalization.mjs | 证据映射、证券、来源和目标价规则 |
| scripts/lib/automation_state.mjs | 预算、缓存、租约及处理状态 |
| scripts/lib/model_client.mjs | 模型适配、预检、结构校验及超时 |
| scripts/lib/approval_guard.mjs | 审批指纹、发布检查与备份 |
| scripts/lib/auto_publish.mjs | 闭环高置信观点自动发布、疑点隔离与原子审计 |
| scripts/validate_automated_batch.mjs | 只读批次验收 |

修改业务规则时同步文档及版本，先运行本地测试，再以有界预算进行真实验证。旧历史回溯脚本不是当前增量入口。
