# XiaoZuoWen Watch · 小作文观察

**把散落的卖方“小作文”，变成能按股票检索、按时间比较、逐条回看原文的 A/H 股研究看板。**

`本地看板 · SQLite`　 `A 股 / 港股`　 `AI 复核 + 人工复核`

## 能做什么

| 研究问题 | 小作文观察怎么回答 |
| --- | --- |
| 最近哪些股票被频繁提到？ | 查看最近 **24 小时 / 72 小时 / 7 天**的热度前 50，对比看多、看空提及。 |
| 某只股票过去都被谁提到过？ | 按公司名或标准证券代码查历史，查看累计提及、方向、时间和观点明细。 |
| 一条观点凭什么入榜？ | 回看原文证据、明确署名的券商、目标价与币种（如有），并查看审批记录。 |
| 模型看不准怎么办？ | 把证券匹配或证据不足的结果留在审核队列；未发布的观点不计入排行。 |

热度反映库内**已发布观点的提及频次**，不代表价格表现、市场共识或投资建议。

## 处理流程

**保存原文 → 识别个股观点 → 匹配证券代码 → 独立复核 → 发布到本地看板**

1. **先留原文，再决定是否结构化。** 从获授权的知识星球来源分页保存原文，按主题去重并保留变更版本。带图片、附件或空正文的主题不进入模型识别，不下载附件、不做 OCR。
2. **只结构化有明确方向的 A/H 股观点。** 使用 Tushare 证券主表和本地别名确认标的；同篇同公司合并，明确的 AH 双指向保留两个代码。未署名不猜券商，目标价只记录原文支持的每股价格及币种。
3. **识别与复核分开。** 先抽取、再单独调用模型复核，随后检查证据、代码与审批状态。存疑交给人工；开启自动发布后，符合门槛的观点才会在备份与复查后写入本地看板。
4. **按预算增量处理。** 已完成的阶段可复用，暂停后按检查点续跑。可限制调用数、输入字符和运行时长；调用次数不是实际费用。

**当前运行方式：** 人工触发，触发后自动推进；自动发布可选，公开模板默认关闭。尚未启用每日定时运行、系统自启动或证券主表自动刷新。模型与发布规则见[工作流说明](docs/PROJECT_WORKFLOW.md)。

## 本地运行

以下步骤仅供权利人及获得书面许可的使用者。需要 **Node.js 22.13+（建议 24 LTS）**，以及各项外部服务的独立授权。示例使用 PowerShell。

```powershell
npm ci
Copy-Item config/workflow.example.json config/workflow.json
```

首次配置时，在本机配置填写获授权的 `group_id`，完成知识星球 CLI 登录，并在 `automation.model` 和 `automation.review_model` 中填写当前账号可用的 Codex 模型。通过 `TUSHARE_TOKEN`、`TUSHARE_TOKEN_FILE` 或 `TUSHARE_CREDENTIAL_ZIP` 提供证券主表凭据。不要提交本机配置或凭据。

```powershell
npm run workflow:init
npm run workflow:sync-securities
npm start
```

打开 [本地看板](http://127.0.0.1:4173/)。首次启动时没有已发布观点，空看板属于正常状态。

### 第一次处理

建议先小批试跑：最近 24 小时，最多 6 篇、4 次模型调用。**运行前须确认有权将所选正文发送给配置的模型服务。**

```powershell
npm run workflow:run -- --hours=24 --limit=6 --batch-size=6 --max-calls=4 --max-chars=80000 --max-minutes=12
npm run workflow:automation-status
```

在看板管理页核对原文、候选观点与审核结果。**已接受不等于已发布**：默认需要在管理页检查并发布，通过后才会出现在热度与历史搜索中。

日常回看最近 7 天使用 `npm run workflow:recent`；手动续跑、批次验收、并行提速和自动发布参数见[工作流文档](docs/PROJECT_WORKFLOW.md)。
